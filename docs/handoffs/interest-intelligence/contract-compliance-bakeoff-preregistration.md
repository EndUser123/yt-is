# Interest inference contract-compliance bakeoff — PREREGISTRATION

Frozen before any measured run against the live corpus. The driver is
`scripts/interest_contract_bakeoff.py`. Any deviation from this document
must be recorded as a post-hoc amendment inline below (marked AMENDMENT)
with its reason; unmarked deviations invalidate the comparison.

## Objective

Repair `FULL_COVERAGE_INFERENCE_COMPLETION_FAILURE` (3 bootstrap attempts,
0 completed; dangling `related_to` x2, invalid `temporal_state` x1;
fail-closed persistence worked correctly) at the CONTRACT layer. This is
contract reliability work. It is NOT semantic tuning: cluster selection,
the 319-cluster full-coverage policy, batch sizing (<=25 clusters/call),
Interest/Goal semantics, temporal-state meanings, confidence thresholds,
and evaluation thresholds are unchanged. Strict final validation and
fail-closed transactional persistence remain mandatory and untouched.

No private Interest evaluation labels are read; nothing under
`P:/.data/yt-is/private/` is read; no Discovery holdout identities are
used. Inputs: unlabeled current-corpus clusters (public corpus metadata
already sent to the provider in normal operation) + synthetic fixtures.

## Provider-native structured output capability (verified pre-freeze)

codex-cli 0.149.1 supports `codex exec --output-schema <file.json>`.
Live probes (2026-08-26, model gpt-5.6-luna, reasoning medium/low):
bare strict JSON returned as the final message; `enum`, `minimum`/
`maximum` numeric bounds, `anyOf` null unions, nested object arrays,
`additionalProperties:false`, `$defs/$ref` all accepted. The bakeoff
tests enforcement in volume; probes only established feasibility.

## Single authoritative contract definition

`ef/inference_contract.py` owns the six vocabularies (kind,
temporal_state, stance, observed_vs_inferred, question status, regret
label) and generates BOTH schemas (batch inference, reconciliation
wrapper). `scripts/build_interest_graph.py` imports those tuples; drift-
guard tests pin PROMPT_TEMPLATE / RECONCILIATION_PROMPT_TEMPLATE enum
lists to the module's lists byte-for-byte. The hand-written prose JSON
shape in the prompts remains the Arm A mechanism, unchanged.

Schema scope is intentionally limited to what JSON Schema can express:
top-level arrays (minItems 1 for inferred_interests), required fields,
enums, confidence bounds [0,1], nullability (anyOf unions), arrays vs
scalars, uniqueItems on interest cluster_ids (mirrors validator dupes=
True), additionalProperties false everywhere. Dynamic same-response
references (`parent`, `related_to`, `questions.interest`,
`regret.related_interests`) and cluster-id membership CANNOT be schema-
expressed and remain in `validate_inference`. Nothing is weakened there.

## Arms

- ARM A — current prose-only JSON mechanism, exactly as shipped
  (prompt template, extraction chain, validator). Unmodified control.
- ARM B — provider-native strict output schema (generated by
  ef.inference_contract) appended to the SAME codex invocation, plus the
  existing semantic validator unchanged.
- ARM C — Arm B plus bounded validator-guided REFERENTIAL repair.

## Repair rules (Arm C scope ceiling)

Repairs never reconsider which Interests exist or what they mean.
1. Deterministic hygiene (no provider call): drop dangling OPTIONAL-edge
   references (`related_to` entries, `regret.related_interests` entries)
   whose target is not among names returned in the same payload. Losing an
   edge preserves object meaning; receipts record every drop.
2. Bounded provider reference repair: remaining REQUIRED-reference defects
   (`questions.interest`, `parent`) go back to the provider ONCE-per-
   attempt up to MAX_REFERENCE_REPAIR_ATTEMPTS=2 total, with the error
   text and the explicit valid-name list, output re-constrained by the
   same strict schema, fully re-validated. Non-reference violations during
   repair fail closed immediately.
3. Enum/bounds/shape violations under B/C are treated as provider/schema
   ENFORCEMENT FAILURES: counted, never repaired, fail closed.
4. Every repair emits receipts: original payload hash, validator error,
   repair method, (attempt n), repaired payload hash. Repaired payloads
   carry result hashes computed by canonical_result_hash.
5. Reconciliation wrapper-level audit decisions (fragment_dispositions)
   are NEVER repaired — missing/duplicate/unknown dispositions fail closed
   in ALL arms. Hooks may only reference-repair `final`.

## Protocol

1. Build the deterministic bootstrap plan from the live inventory at run
   start (mechanically verified pre-freeze: 319/319 eligible clusters,
   13 batches, plan_id `plan_01b09359b3f05784`). The SAME plan ids feed
   all arms. Coverage validated before any call.
2. Batches execute interleaved (b001 x A/B/C, b002 x A/B/C, ...) so
   time drift and caching effects hit arms equally.
3. NO abort on invalid outputs: every planned batch executes for every
   arm so the taxonomy is complete (39 batch calls nominal).
4. One automatic retry ONLY for provider-execution-class failures
   (nonzero exit, timeout 580s, missing agent message); retried flag
   recorded; semantic violations are data points, never retried.
5. Reconciliation runs per arm over THAT arm's own validated fragments
   (batches that failed contribute no fragments; skip-if-empty recorded),
   using big.run_reconciliation_tree with the arm's invoke style and,
   for C, the default-off repair_hook seam (final-only hygiene+repair).
6. Persistence: NONE. store=False always. Artifacts (prompts, raw event
   streams, payloads, receipts, metrics) under
   P:/.data/yt-is/ef/interest-inference/bakeoff-<ts>_<planid>/.
7. Tokens/cost from codex --json turn.completed usage events; latency =
   wall clock per call. Note (pre-freeze observation): codex -C P:/
   carries ~74k input tokens of scaffold context per call in probes; all
   arms share it, so comparisons stay internally valid.
8. Synthetic fixtures mode (--fixtures) runs offline: canonical valid
   fixture passes both layers; corruption fixtures prove classifier +
   schema-checker behavior. Fixture results are correctness checks for
   the harness, not compliance-rate inputs.

## Per-call metric definitions (frozen)

- attempted: one per planned (arm,batch) regardless of retries.
- structurally_valid: usable JSON object extracted.
- schema_violation (B/C): conformance errors against generated schema —
  provider/schema enforcement failure class.
- semantic_valid_first_pass: validate_inference passes BEFORE any repair.
- repaired: payload admitted only after deterministic hygiene and/or
  bounded reference repair (counts + dropped-edge tallies reported).
- semantic_valid_final: validated payload that would feed fragments.
- unrecoverable: no semantic_valid_final after exhausted bounds.
- Failure classes: provider_exec_error | provider_timeout |
  no_agent_message | no_json_extractable | schema_violation_detail |
  semantic_reference_dangling_parent/question/related_to/regret_ref |
  semantic_other (bad cluster ids, dupes, empty fields, cycles, enums).
- Reconciliation measured separately per arm: group calls attempted /
  valid / repaired / failed; tree completion; stage count; reduction
  sanity (fail-closed on non-convergence preserved from production code).

## Selection rule and DECISION mapping (frozen)

Rank arms by semantic_valid_final rate over attempted; tie-break: fewer
unrecoverable -> fewer repairs applied (minimal intervention) -> lower
median latency. The candidate for adoption must ALSO have completed its
own reconciliation tree in-phase (otherwise the compounding pipeline is
still not reliable end-to-end).

- INSUFFICIENT_PROVIDER_CAPABILITY: schema rejected/ignored in volume
  use despite pre-freeze probes (enforcement nonexistent).
- CONTRACT_RELIABILITY_NOT_SUPPORTED: no arm meets the bar below.
- CONTRACT_RELIABILITY_SUPPORTED: winning arm shows
  semantic_valid_final == 13/13 batches AND <=1 unrecoverable across all
  its calls (batches+reconciliation), with its reconciliation tree
  completing through final validated disposition. Rationale: a 13-batch +
  multi-stage tree compounds ~15+ provider calls; anything short of
  near-certainty per call keeps 0/3 outcomes likely.

If SUPPORTED: wire the SELECTED mechanism (B minus repair if B wins;
with repair hooks only if C wins) into the production bootstrap path;
rerun the >=3 full SHADOW bootstraps requirement on the wired path; no
persistence during shadows; require 3/3 completions THROUGH final
validated reconciliation before recording the defect provisionally
repaired. Shadow results are reliability evidence, not Interest quality
evidence.

## AMENDMENT 2 (2026-08-26, pre-results; live provider bisect)

The generated schema previously set `uniqueItems: true` on interest
`cluster_ids` (mirroring validator dupes=True). Live bisection against
codex gpt-5.6-luna structured output (2026-08-26) shows the endpoint
rejects `uniqueItems` with HTTP 400 while accepting `minItems`,
`$defs`/`$ref`, `enum`, numeric bounds, and anyOf-null unions. Provider
enforcement is therefore NOT available for duplicate cluster ids.

Change: `uniqueItems` removed from the generated schema. Enforcement of
no-duplicate interest `cluster_ids` remains exactly where it was — the
mechanical validator (`validate_inference`) — and violations there count
as semantic failures (unrecoverable under every arm), never repairs.
Selection rule and DECISION mapping unchanged. This is a recorded
provider-capability limitation relevant to the final reliability claim:
strict structured output on this endpoint cannot express uniqueness
constraints.
